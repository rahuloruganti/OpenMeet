# Privacy: Windows capture preview

This build stores meeting metadata, typed notes, fictional fixtures, and settings in a local SQLite database. Export uses a folder explicitly chosen through the native picker. Windows desktop capture code writes separate microphone/system WAVs and timing JSONL locally under the app-data `audio/<meeting ID>/` directory. Capture qualification has not passed; macOS capture is unsupported. Simulation opens no audio devices. **Merge model discovery.** When you press Connect / refresh or save a Merge model, Rust sends one authenticated `GET https://api-gateway.merge.dev/v1/models` (paginated, bounded, redirects refused) carrying only your API key; no meeting content is sent by that request. The key is read from the `OPENMEET_LLM_API_KEY` environment variable by Rust on explicit import and stored in the OS keychain; it is never sent to the webview, SQLite, or logs, but the environment variable itself stays in your shell or profile until you remove it. **Local speech-to-text.** Only when you press Download in Settings, the app fetches a pinned whisper.cpp Windows build (release b5454, github.com) and the Whisper "small" and Silero VAD model files (huggingface.co), rejecting anything whose size or SHA-256 differs. Finalized WAV tracks are then transcribed by that engine as a local subprocess; audio is never uploaded. Transcript text is stored unencrypted in the local SQLite database. The engine receives file paths and model paths only; transcript text is not logged.

**Summaries.** Pressing Enhance notes shows what will be sent; only after you confirm does the backend POST your notes and the transcript text (never audio) to `https://api-gateway.merge.dev/v1/chat/completions` with the model you saved. Each send needs fresh confirmation, nothing is generated automatically, and Merge and the model provider's own terms govern that text once sent. The result is stored with its provider and model and never replaces your notes; earlier summaries are kept. Very long meetings are refused locally rather than truncated. There is no telemetry or updater.

The packaged frontend has no permission to read arbitrary files, register shortcuts, open dialogs directly, or call arbitrary network services. Merge model discovery and summaries are performed by Rust, not by the webview. Rust exposes specific operations; its folder picker is the only way to change the export destination. Development mode also uses Vite's localhost server.

The database, audio, timing files, and exported Markdown are **not encrypted**. Device administrators, OS backups, and sync software can access them. Choosing a cloud-synced folder can upload exports even though OpenMeet makes no upload request. There is no retention cleanup or in-app deletion UI yet; original and partial audio files are retained even after capture failures. **Recover audio** reads an interrupted recording's partial WAV and writes a repaired copy (`<track>.recovered.wav`) beside it; the original partial file is kept unchanged, so recovered audio takes roughly twice the disk space. Export settings can leave the summary or transcript out of new Markdown snapshots; existing snapshots are not changed. Close the app before manually removing its app-data directory; exported files must be removed separately.

Autosave waits 400 ms and serializes writes. Stop requests capture shutdown without waiting for note saving; failed drafts remain on screen. Graceful close flushes notes and refuses to quit on save failure. A forced process termination or power loss can lose edits not yet saved. Use synthetic data during this unvalidated preview.

Real recording requires participant consent acknowledgement and OS/device access. System capture can include unrelated application audio. Before qualification or cloud processing ships, validate pause privacy and local-only egress, and extend this policy for model downloads and provider disclosure. Those checks have not passed.
