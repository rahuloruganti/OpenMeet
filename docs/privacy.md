# Privacy: Windows capture preview

This build stores meeting metadata, typed notes, fictional fixtures, and settings in a local SQLite database. Export uses a folder explicitly chosen through the native picker. Windows desktop capture code writes separate microphone/system WAVs and timing JSONL locally under the app-data `audio/<meeting ID>/` directory. Capture qualification has not passed; macOS capture is unsupported. Simulation opens no audio devices. The local model selector reads installed-model metadata only from `http://127.0.0.1:11434/api/tags` when you refresh or save a choice. Requests have bounded time/body size, bypass proxies, and refuse redirects. Models reported as remote/cloud are excluded; no prompt, audio, or notes are sent. No Ollama/model installation happens automatically. Merge Gateway support is limited to credential storage and model discovery: when you press Connect / refresh or save a Merge model, Rust sends one authenticated `GET https://api-gateway.merge.dev/v1/models` (paginated, bounded, redirects refused) carrying only your API key. No notes, transcripts, or audio are sent, and no summary or inference request exists. The key is read from the `OPENMEET_LLM_API_KEY` environment variable by Rust on explicit import and stored in the OS keychain; it is never sent to the webview, SQLite, or logs, but the environment variable itself stays in your shell or profile until you remove it. **Local speech-to-text.** Only when you press Download in Settings, the app fetches a pinned whisper.cpp Windows build (release b5454, github.com) and the Whisper "small" and Silero VAD model files (huggingface.co), rejecting anything whose size or SHA-256 differs. Finalized WAV tracks are then transcribed by that engine as a local subprocess; audio is never uploaded. Transcript text is stored unencrypted in the local SQLite database. The engine receives file paths and model paths only; transcript text is not logged.

**Summaries.** Pressing Enhance notes shows what will be sent; only after you confirm does the backend POST your notes and the transcript text (never audio) to `https://api-gateway.merge.dev/v1/chat/completions` with the model you saved. Each send needs fresh confirmation, nothing is generated automatically, and Merge and the model provider's own terms govern that text once sent. The confirmation names the template (General, Stand-up, One-to-one) and the number of requests. A meeting too long for one request is split on segment boundaries: each part of the transcript goes in its own request, then one more request combines those partial notes with your notes; above 9 requests the summary is refused locally rather than truncated, and if the content changes after you confirm, nothing is sent. The result is stored with its provider, model and template and never replaces your notes; earlier summaries are kept and can be viewed in the Summary tab (export uses the latest). **Ask this meeting** sends one question with that meeting's notes and transcript text (never audio, never other meetings) in one request, again only after its own confirmation; the answer is shown and not stored. Copy buttons put summary text on the system clipboard, where other apps can read it. There is no telemetry or updater.

The packaged frontend has no permission to read arbitrary files, register shortcuts, open dialogs directly, or call arbitrary network services. Merge model discovery and summaries are performed by Rust, not by the webview. Rust exposes specific operations; its folder picker is the only way to change the export destination. Development mode also uses Vite's localhost server.

The database, audio, timing files, and exported Markdown are **not encrypted**. Device administrators, OS backups, and sync software can access them. Choosing a cloud-synced folder can upload exports even though OpenMeet makes no upload request. Titles, notes, transcript text and summaries are also copied into a local full-text search index inside the same database. There is no automatic retention cleanup: audio, including partial files from failed captures, stays until you delete it. **Delete audio** removes a meeting's WAV and timing files, and only files located directly in that meeting's app-data `audio/<meeting ID>/` folder; its notes, transcript and summaries are kept. **Delete meeting** does the same and then removes the meeting, its notes, transcript, summaries and search-index entries from the database. Both need the meeting title typed to confirm, are refused while that meeting is recording, and cannot be undone in the app. Deletion is not secure erasure: OS backups, sync copies, and unreclaimed database or disk space can still hold the data. Exported Markdown snapshots are never touched and must be removed separately. Close the app before manually removing its app-data directory.

Autosave waits 400 ms and serializes writes. Stop requests capture shutdown without waiting for note saving; failed drafts remain on screen. Graceful close flushes notes and refuses to quit on save failure. A forced process termination or power loss can lose edits not yet saved. Use synthetic data during this unvalidated preview.

Real recording requires participant consent acknowledgement and OS/device access. System capture can include unrelated application audio. Before qualification or cloud processing ships, validate pause privacy and local-only egress, and extend this policy for model downloads and provider disclosure. Those checks have not passed.
