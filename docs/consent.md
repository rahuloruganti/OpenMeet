# Recording consent

The Windows and Apple Silicon previews record selected microphone and system-output devices. macOS capture requires 14.2 or newer and refuses outputs with their own input. Simulation/sample creation is removed; historical fictional entries remain labeled. Full capture qualification and macOS permission-denial checks remain open.

Before using real recording, inform participants and obtain whatever consent applicable law and organizational policy require. The UI requires an acknowledgement before starting. A visible indicator or a local OS permission prompt is not participant consent. System capture can include unrelated application audio; headphones do not change recording obligations.

Never rename simulated results as actual recordings. Keep the preview warning until capture passes its platform and privacy gates. The code has recording indicators and pause controls, but real-machine paused-audio privacy, device failures, and timing still require validation. Qualification recordings require explicit authorization and identifiable synthetic speech/tones, not private meetings.

Recording consent does not authorize cloud processing. Recording-only is the default. Automatic live transcription, final transcription, and optional summary require a separate review before start. That review names destinations, models, both tracks, future recorded audio, saved-note scope, recording horizon, post-stop deadline, and audio/request/UTF-8 text limits. Live plus final transcription can incur separate charges. Relevant changes require renewed review.

Manual cloud transcription separately confirms destination, model, tracks, upload size, and request count. Manual summaries and questions separately confirm text submission. An explicit retry reviews the existing stopped recording with fresh limits and starts no capture. A previous request may already have been billed. Provider retention and billing apply; cancellation cannot recall uploaded content. Local Whisper does not submit audio to a provider.

Pausing excludes new audio under the implementation. Previously submitted work using accepted pre-pause audio may finish while paused. Stopping does not imply processing has finished. Save and quit interrupts unfinished processing, and restart never repeats requests automatically. Hardware pause privacy and real-provider behavior remain unqualified.
