# Recording consent

The Windows and Apple Silicon previews have a real recording action for a selected microphone and system-output device, plus a separate simulation that opens no audio devices. The sample meeting is fictional. Real capture has not passed hardware qualification. macOS requires 14.2 or newer, refuses an output that also has an input, and has not had permission denial tested. Transcription remains Windows-only.

Before using real recording, inform participants and obtain whatever consent applicable law and organizational policy require. The UI requires an acknowledgement before starting. A visible indicator or a local OS permission prompt is not participant consent. System capture can include unrelated application audio; headphones do not change recording obligations.

Never rename simulated results as actual recordings. Keep the preview warning until capture passes its platform and privacy gates. The code has recording indicators and pause controls, but real-machine paused-audio privacy, device failures, and timing still require validation. Qualification recordings require explicit authorization and identifiable synthetic speech/tones, not private meetings.
